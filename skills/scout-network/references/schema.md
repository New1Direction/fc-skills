# Normalized evaluator input, version 1

Read `examples/synthetic.json` for a complete fictional input. All listed fields are required; use only explicitly permitted nulls. Unknown fields, duplicate JSON keys, floating JSON numbers, NaN/Infinity, duplicate case IDs and duplicate wallet/chain/token discoveries are rejected. Monetary and quantity values are **nonnegative decimal strings**, without exponents, sign or leading zeros; exact returns are serialized as `{numerator, denominator}` string pairs, never rounded floats. Timestamps are whole-second UTC `YYYY-MM-DDTHH:MM:SSZ`. `available_at >= event_at` is required.

| Object | Required fields and meaning |
| --- | --- |
| Root | `schema_version: 1`, `decision_cutoff`, `source_kind`, `cohort`, `scenario`, `wallets`, `cases` |
| `cohort` | `rule`, `frozen_at`, `available_at`, `window_start`, `window_end`, `coverage_status`, `coverage_available_at`, `expected_case_count`, `exclusions`, `source_refs` |
| `scenario` | `currency`, `follower_delay_seconds`, `entry_budget`, `hold_seconds`, `max_execution_lag_seconds`, `execution_mode`, `thresholds` |
| Wallet | `id`, `selected_at`, `selection_available_at`, `selection_rule`, `source_refs`, `relation_group`, `relation_available_at`, `relation_source_refs` |
| Case | `id`, `wallet_id`, `chain`, `token`, `source_kind`, `discovery`, `access`, `entry`, `exit` |
| `discovery` | `event_at`, `available_at`, `source_refs` |
| `access` | `kind`, `event_at`, `available_at`, `source_refs` |
| `entry`/`exit` | Null or `status`, `event_at`, `available_at`, `source_refs`, `evidence_kind`, `currency`, `quote_amount`, `token_quantity`, `fees`, `assumptions` |
| Exclusion | `reason`, `count`, `source_refs` |
| Non-null thresholds | `origin`, `min_evaluated_cases`, `min_distinct_tokens`, `max_unresolved_fraction`, `max_token_concentration_fraction` |

`source_kind` is `observed`, `synthetic`, or `unknown`, both at root and case level. An observed root cannot contain non-observed cases; unknown provenance prevents that case from evaluation. Mixed hypothetical/real input must never be presented as observed: keep observed and synthetic runs separate for useful conclusions. A synthetic report may show demonstration ranks, explicitly marked synthetic.

The cohort window is inclusive and must end by the cutoff. `expected_case_count` is the number of discoveries that the frozen cohort rule requires and that were available at the cutoff, independent of whether their follower outcomes succeeded; it is an integer or null. Coverage is `complete`, `partial`, or `unknown`. `coverage_available_at` is the first availability of the coverage status, count and exclusions assertion; if later than cutoff it cannot establish historical completeness. A null/mismatched count, non-complete coverage, or any positive excluded count blocks all ranking. `exclusions` records known omitted eligible cases; outside-rule selection must be explicit in `rule`, not quietly removed. Selection/freeze and their availability must be no later than `window_start` to rank. Cohort `available_at` dates the frozen selection rule, separately from the later coverage assertion. Source references to both the frozen selection manifest and coverage assertion are required for ranking.

Wallet IDs should include chain and canonical wallet address. Chains and tokens must be normalized upstream: the helper treats their strings literally and cannot detect aliases/case-equivalent addresses. `relation_group` and `relation_available_at` are both null for unknown relationships. Otherwise the group is a documented dependence hypothesis; it is usable only with references available by cutoff. Unknown relationships cannot be counted as independent.

Access `kind` is `ordinary_buy`, `privileged_allocation`, `insider`, or `unknown`. Evidence first available after cutoff is unknown for ranking even if it describes an earlier event. Privilege remains a visible unfollowable case. Discovery first available after cutoff or outside the window is retained in excluded audit rows and does not enter wallet score denominators. Every other discovery enters the denominator, including immature, failed, unknown and unfollowable cases.

Scenario `execution_mode` is `executed` or `simulated`; each fill's `evidence_kind` may also be `quote` or `unknown`, which cannot satisfy either scenario. No mode mixing. A fill `status` is `filled`, `failed`, or `unknown`. `quote_amount`, `token_quantity`, and `fees` may be null for unavailable quantities/costs. All are needed to evaluate a filled case. `quote_amount` is the entry payment or gross exit proceeds after price impact/taxes but before the separately listed costs. `fees` contains all additional quote-currency costs exactly once; a supported zero is `"0"`. `assumptions` must state route, historical state, capacity and cost coverage/conversions or explicitly record their absence. Unknown components require null total fees, not an unsupported zero. `currency` must match the scenario's chain-qualified asset identifier exactly even for failed fills.

Entry quantity must be positive; exit quantity must match exactly. Unknown/partial exits never receive an inferred terminal value. Maturity conservatively requires the latest permitted entry and exit times to have passed by cutoff; both fills must also have become available. Positive fees may exceed sale proceeds, producing an exact loss larger than the original principal where appropriate.

`thresholds: null` uses documented uncalibrated engineering defaults: 3 evaluated cases, 3 distinct tokens, unresolved fraction 0, capital/positive-profit concentration at most 0.5. Non-null `origin` is `user_explicit` or `engineering_default_uncalibrated`; both minimums are integers >=1, fractions lie in [0,1]. Use `user_explicit` only for actual user choices. Fractions use all visible picks for unresolved share; concentration uses completed cases and the largest positive token profit's share of all positive token profits. If there are no positive profits, that share is null.

Net per completed case is `(exit.quote_amount - exit.fees) - (entry.quote_amount + entry.fees)`. Return divides this by entry amount plus entry fees. Ranking sorts eligible wallets by **aggregate completed-case net / aggregate completed-case spend**, descending, breaking exact ties by wallet ID. The median of case returns is also reported. These are descriptive rankings of a declared sample, never forecasts.

Limits: 8 MB input, 200 wallets, 10,000 cases, 100 exclusions, 50 references per evidence object, 2,048 characters per text/reference, 100 characters per decimal string, scenario durations <=31,536,000 seconds. Input SHA-256 covers original file bytes. The CLI writes sorted strict JSON to a new output file with exclusive create; existing paths are refused. All normalized evidence (including excluded/future rows) is retained for audit with original timestamps; use only evaluated rows for cutoff claims. Output references cannot establish that upstream data is authentic or properly normalized.
