# Retained-observation schema v1

Use `assets/synthetic-example.json` as a structural example only. Root keys: `schema_version: 1`, `source_kind`, `cutoff`, `identity`, `evidence`, `windows`, and optional `thresholds`. Unknown keys, duplicate JSON keys, floats, nonfinite numbers, oversized structures, invalid counts, and negative amounts are rejected. Input is limited to 2 MB, 256 windows, 1,000 evidence records, 5,000 buyers/window, depth 16, and 100,000 values. UTC timestamps must use `YYYY-MM-DDTHH:MM:SSZ`; windows are half-open `[start,end)`. Counts and slippage basis points are JSON integers; quote/token amounts and decimal thresholds are strings with at most 40 integer and 18 fractional digits. Exact arithmetic uses Fraction/Decimal; output numbers contain exact rational strings plus decimal displays rounded to 12 places.

`identity` is an exact object with nonempty string fields `chain`, `token`, `token_unit`, `quote_unit`, `pool_scope`. Use canonical identifiers including quote asset/decimals, never an ambiguous ticker. Preserve exact case where chain identifiers are case-sensitive. Identity comparison is exact; the helper does not convert wrapped assets, USD denominations, token units, or chain addresses. `pool_scope` identifies the same declared set of pools/routes in every window. Adding a pool changes scope and needs a separate analysis.

Evidence rows require `id`, `source_kind` (`observed`, `synthetic`, `unknown`), `available_at` (timestamp or null), and `reference` (retained file/transaction/source URI or descriptive retained-record locator). Optional `sha256` is a 64-character lowercase digest. The helper validates format and links but does not open or authenticate evidence. Root source kind must be the conservative aggregate: synthetic if any evidence is synthetic, else unknown if any is unknown or none exists, else observed. The input hash is calculated from exact input bytes in CLI mode; the Python API hashes canonical JSON when no hash argument is supplied. Source evidence hashes are declarations, not validated file hashes.

Each window requires:

| Field | Meaning |
| --- | --- |
| `id`, `role` | Unique ID; role is `active_history`, `dormancy`, or `current` |
| `start`, `end`, `available_at` | UTC bounds and latest availability of **all** enclosed observations, cohort histories, grouping decisions, snapshots, depth estimates, coverage, and comparability assertions |
| `identity`, `evidence_refs` | Exact scoped identity and nonempty references supporting all supplied window fields |
| `activity_coverage` | `complete`, `partial`, or `unknown` for exhaustive trade/volume observation of this scope |
| `buyer_coverage` | Same enum for the complete end-user buying cohort in this window |
| `history_coverage` | Same enum for token-wide purchase history since token inception, sufficient to support every supplied first-purchase date |
| `relationship_coverage` | Same enum for relationship review of all current buyers; complete means every buyer was reviewed under a disclosed rule, not that independence is provable |
| `comparability_events` | Empty list for affirmatively reviewed stability; otherwise `rebase`, `migration`, `new_pool`, `quote_asset_change`, `unit_change`, and/or `unknown` |
| `metrics` | Object with optional/null `trades` and `quote_volume`; missing activity prevents the decision |

The window's `available_at` must be at or after its end. A null availability means unknown, not current. Every referenced evidence record must also have availability at or before the cutoff. Window availability is an aggregate contract: use the latest publication/review time across **every feature**, not just the trade timestamps. If one feature arrived later, either set the later aggregate availability (excluding the window) or omit that feature and explicitly reduce its coverage. Do not move newly discovered funding groups into an earlier backtest. Timestamps for first purchases and incumbent snapshots are event times; their availability is covered by the enclosing window and evidence references. Cutoff checks run before any feature calculation.

Optional window fields:

- `buyers`: rows with `wallet`, positive `buy_quote`, `first_buy_at` (timestamp or null), `dependency_group` (string or null). Exactly one aggregate row per end-user buyer. Full token history is required to classify a buyer as new or returning. Null group under complete relationship coverage means reviewed with no identified link; under incomplete coverage it means unknown. Assign identical strings to suspected dependent wallets. The helper never infers links itself.
- `incumbents`: null or object with `snapshot_at`, `buy_quote`, `sell_quote`. Retain membership and snapshot evidence upstream. Snapshot after current start is excluded from incumbent analysis. All swaps must be against the preselected cohort; missing object yields unknown distribution.
- `liquidity`: null or object with optional/null `quote_reserve_start`, `quote_reserve_end`, `depth_quote_start`, `depth_quote_end`, `token_units_start`, `token_units_end`, `slippage_bps`. Use the same measurement method, route scope, and slippage target at both endpoints. Quote-unit amounts must not be marked-to-USD values when the quote asset is not USD. Missing reserve/depth/slippage data yields unknown improvement.

Buyer count cannot exceed trade count; supplied buyer capital and incumbent gross flows cannot exceed total quote volume. For the same exact chain, token, and wallet, all known first-purchase dates must agree and precede the end of every recorded buying window, even when an earlier window's first-purchase date is unknown. Contradictory histories are rejected regardless of input ordering. These checks detect internal inconsistencies, not omitted trades. Exactly one current window is required. Full dormancy/resurgence classification requires at least one active-history window then two dormant windows then current, equal duration, contiguous, and nonoverlapping; any excluded window leaves the full sequence indeterminate. Native analysis intentionally requires this narrow structure. For gaps or additional epochs, present a narrower evidence report instead of padding zero windows.

Optional thresholds accept keys shown in output: `max_dormant_trades_per_day`, `max_dormant_active_fraction`, `min_current_trades_per_day`, `min_resurgence_multiple`, `min_new_buyers`, `min_new_groups`, `max_group_capital_share`, `min_new_capital_share`. Buyer/group minimums are positive integers; other thresholds are positive decimal strings. Dormant fraction must be below 1, resurgence multiple above 1, and both capital-share thresholds at most 1. Defaults are explicit, uncalibrated engineering settings. Record overrides and rationale.

CLI errors return status 2 and do not replace an existing file. Output creation uses exclusive mode; choose a fresh path. Output includes evidence declarations, exclusions, coverage, rates, cohort amounts, group concentration, incumbent net selling, and liquidity changes. Synthetic classifications remain synthetic; unknown source kind cannot support an authenticated observation claim.
