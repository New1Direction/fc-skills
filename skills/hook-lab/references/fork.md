# Local fork execution and evidence

`simulateFork(request, {anvilPath, rpcUrl})` in `scripts/fork.mjs` executes one `hook-lab.call.v1` request on a newly spawned Anvil child. The remote `rpcUrl` receives only read requests from this collector. Local transaction submission uses a private loopback address allocated for that child. There is no caller-supplied write endpoint, transaction signature, private key input, or live submission mode.

Anvil must already be installed. The process is started without a shell, with `--host 127.0.0.1`, the requested fork block, chain ID 4663, and `--accounts 0`. Disabling default accounts matters: Anvil's normal development wallets are funded and would otherwise contaminate wallet-specific balance evidence. The collector does not change balances, allowances, contract code, storage, roles or owner lists. It impersonates exactly the requested sender on the disposable local fork; a contract sender is rejected because that would not reproduce an ordinary externally owned account transaction. This does not prove ownership of the requested wallet or authorize a real transaction.

The source chain ID and canonical block number/hash are checked before startup. Local `anvil_nodeInfo`, `anvil_metadata`, the fork header and the client version must agree. The transaction executes against the state at that block, inside the next **local** block. It is not a replay at an earlier transaction's precise prestate. The local receipt's block must have the requested block as its parent. The source block is checked again afterward. Failure or a changed source header yields `INCOMPLETE`.

Each ERC-20 balance is read through `balanceOf(owner)` before and after the transaction. Native balances are collected for the sender and all explicitly tracked token owners. Observations retain raw RPC parameters and results, including the actual mined transaction, receipt, logs and balance return values. Token amounts remain integer base units. The zero address is reserved for a native-currency expectation and cannot appear as an ERC-20 `balance_tokens` address. Native expectations use the **raw native balance change, including local gas**. A downstream calculation may add back the separately retained local gas cost to isolate the native transfer component.

The sender must have enough native balance at the fork origin to cover the requested value plus the supplied gas limit at the local gas price. No funding is added to make a request succeed. The transaction's chosen local gas price and mined gas usage are retained. The product is local EVM gas cost only: Robinhood/Nitro L1 data fees, Nitro-specific precompiles, transaction inclusion conditions and future execution remain outside this Anvil model. All-in Robinhood cost is explicitly `null`.

Output statuses are `FORK_EXECUTED_AT_BLOCK`, `FORK_REVERTED_AT_BLOCK` and `INCOMPLETE`. Successful execution with failing balance expectations still reports the actual execution status and includes `EXPECTATION_FAILED`. It is not qualified for the requested economic outcome. Synthetic contexts and unverified source mappings remain explicit issues. A success has the scope of the exact request and parent block; no future-fill or profitability promise follows.

`validateForkEvidence(report)` recomputes digests, binds source and fork identities, sender, calldata, amount, gas, raw receipt, raw transaction, logs and before/after balance observations, and recomputes deltas and expectations. It rejects state-seeding methods, source writes and substituted senders in a complete transcript. This is retained-evidence consistency checking, **not authentication of the RPC provider or a cryptographic execution proof**. A supplied JSON file remains supplied evidence.

Each run has a 30-second deadline, at most 16 token/owner pairs and a 1 MiB evidence/response cap. Startup, RPC failure, excessive output, incompatible Anvil versions or missing receipts are incomplete evidence. The child is terminated in cleanup; a best-effort local snapshot revert runs first when time remains. Fork URLs, process arguments and stdout/stderr are omitted from reports because they may contain provider credentials. The Anvil fork URL still exists in the local process arguments while running, so use the tool on a machine with an appropriate local trust boundary.

Primary references: [Anvil JSON-RPC methods](https://www.getfoundry.sh/anvil/rpc-methods), [Anvil options](https://www.getfoundry.sh/reference/anvil/anvil), and [Foundry implementation of node metadata](https://github.com/foundry-rs/foundry/blob/master/crates/anvil/src/eth/api.rs). A supported Anvil version must expose `anvil_metadata.forkedNetwork`; the collector fails closed instead of guessing when it is unavailable.
