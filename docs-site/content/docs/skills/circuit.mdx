Use CIRCUIT to examine route settlement, wallet balance changes, refunds, and results at different trade sizes.

## What to provide

The exact wallet, router, pool identities, block, trade sizes, approvals, and cost assumptions. Measured simulations need archive RPC access and Anvil.

## Ask your agent

```text
Use CIRCUIT to test this route at these trade sizes.
Show wallet balance changes, refunds, fees, and failures.
Keep the route unsigned and explain any unsupported behavior.
```

## What you get

An unsigned route, preflight checks, and supported simulation results with conditional cost estimates.

The adapter targets Universal Router 2.1.1; its correspondence to the live deployment still needs verification. Simulations do not guarantee live execution.

<details>

**Runtime:** Node.js 24+; Anvil for forks.

Run from the repository root with a new output path. This example uses simulated data and makes no live network requests.

node skills/circuit/scripts/circuit.mjs demo --out ../fc-circuit-demo-new

Open the output to explore the report before adding your own data.

<details>
<summary>Technical details and source</summary>

- Compilation targets the pinned Universal Router 2.1.1 source ABI; live Robinhood runtime correspondence remains unverified.
- Native entry supports an ordinary EOA; contract wallets/vaults, flash borrowing, cross-chain legs, taxes, and rebases need other verified adapters.
- Nonzero hooks require exact investigation; a passing call does not establish generic hook safety.
- Anvil runs the next local block from the parent, not historical intrablock state or a proven Nitro equivalent.
- The tool does not seed live-wallet funding/approvals, sign permits, submit trades, or claim a sampled size is globally optimal.
