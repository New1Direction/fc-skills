Use PULSE to observe Robinhood Chain data, maintain supported V4 pool state, and measure when different providers report the same events.

## What to provide

Configured RPC providers, exact pool identities, and observation windows. Node setup also needs a host you control and verified chain configuration.

## Ask your agent

```text
Use PULSE to compare these Robinhood Chain data sources.
Measure arrival times for the same events and report missed data.
Keep provisional pool observations clearly labeled.
```

## What you get

An event journal, provider timing comparisons, supported pool-state reports, and optional node setup plans.

PULSE’s filtered event collection does not capture every transaction. Use WATCHTOWER for full included-block capture.

<details>
<summary>Try a local example</summary>

**Runtime:** Node.js 24+.

Run from the repository root with a new output path. This example uses simulated data and makes no live network requests.

```sh
node skills/pulse/scripts/pulse.mjs pools --registry skills/pulse/assets/pools.synthetic.json --blocks skills/pulse/assets/blocks.synthetic.json --out ../fc-pulse-report-new.json
```

Open the output to explore the report before adding your own data.

</details>

<details>
<summary>Technical details and source</summary>

- Filtered logs do not capture every included transaction; WATCHTOWER handles full-block intake.
- Raw sequencer-feed capture does not execute Nitro, verify signatures, or reveal an unsequenced private queue.
- V4 state marks are not trade-size quotes or arbitrary-hook execution models.
- Software and templates do not establish a running synced node, production capacity, or the fastest source; actual host measurement is required.
