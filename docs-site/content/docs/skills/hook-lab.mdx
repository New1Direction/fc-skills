title: "HOOK LAB"
description: "Understand a pool\u2019s custom fees and rules."
---

A V4 hook is code that adds custom behavior to a pool. Use HOOK LAB to investigate how that code affects a specific wallet and swap.

## What to provide

The exact pool and hook addresses, block, wallet call, and available code or configuration. Fork simulations also need archive RPC access and Anvil.

## Ask your agent

```text
Use HOOK LAB to investigate this V4 pool’s hook.
Explain its fees and restrictions for this wallet call.
Show what was verified and what still needs testing.
```

## What you get

An investigation of the deployed hook, supported fee calculations, and available wallet-call evidence.

A passing simulation is not a security audit. The bundled Pons V2 fee adapter does not provide a complete swap quote.

<details>
<summary>Try a local example</summary>

**Runtime:** Node.js 24+; Anvil for forks.

Run from the repository root with a new output path. This example uses simulated data and makes no live network requests.

```sh
node skills/hook-lab/scripts/hook-lab.mjs pons-fees --input skills/hook-lab/assets/pons-fees.synthetic.json --out ../fc-hook-lab-report-new.json
```

Open the output to explore the report before adding your own data.

</details>

<details>
<summary>Technical details and source</summary>

- Pons V2 here names the Pons hook family; it is not Exit Doctor’s Uniswap V2 AMM adapter.
- The Pons fee helper is not a full V4 traversal quoter or automatic build/runtime verification.
- Native positive qualification covers an exact direct two-asset swap, not an arbitrary size range or same-asset arbitrage.
- Published candidates and successful local checks do not establish a live mainnet route, audit, or consumer execution approval.
