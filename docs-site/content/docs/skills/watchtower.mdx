---
title: "WATCHTOWER"
description: "Retain every RPC-reported included transaction in an explicit monitored interval."
---

Use it for chain-wide Robinhood capture, receipt coverage, gap recovery, research dispatch, and measured source latency.

**Runtime:** Node.js 24+.

## How it works

1. Set an explicit first block and collect full RPC block arrays before applying research filters.
2. Prioritize fresh tail capture while bounded workers recover older gaps; reconcile every reported receipt independently.
3. Persist SQLite WAL state, restart/reorg recovery, coverage cursors, invalidations, and outbox retractions.
4. Run classification/enrichment workers separately and dispatch exact configured address/topic matches for review.

## What to provide

- A primary source, optional comparison source, explicit from_block, and source variables.
- Durable database path, bounded storage/concurrency policy, and operator host for continuous use.
- Optional exact-address/topic research policies and downstream durable consumer cursors.

## What you get

- Full retained included transactions, receipts, status/coverage reports, and recoverable event history.
- Classifications and reviewable research dispatch/outbox records.
- Separate arrival, durable-capture, receipt-completion, and worker-completion latency evidence.

## Run the offline example

Run from the repository root. This uses invented fixtures, makes no live network requests, and needs a fresh output path.

```sh
node skills/watchtower/scripts/watchtower.mjs demo --out /tmp/msk-watchtower-demo-new
```

This command was run successfully while preparing the documentation. Inspect the resulting directory before replacing the example inputs with your own evidence.

## Coverage and limits

- Every transaction means every RPC-reported included transaction within the declared retained interval, not rejected submissions, all history since genesis, or private pending activity.
- Internal calls, internal native transfers, and revert reasons remain untraced without another verified adapter.
- Workers do not automatically execute other skills or submit Ape trades.
- No deployed host, sustained mainnet capacity, or fastest-provider result follows from installation or synthetic benchmarks.
