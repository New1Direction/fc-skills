Use Exit Doctor to estimate what selling a position could return after price impact and supported costs.

## What to provide

The exact token pair, pool, position sizes, and block to examine. Add cost estimates and wallet-call evidence when available.

## Ask your agent

```text
Use Exit Doctor to compare exits for these position sizes.
Show price impact, known costs, and missing assumptions.
Label quotes separately from wallet simulations.
```

## What you get

A size-by-size comparison of estimated proceeds, price impact, costs, and supplied liquidity scenarios.

Built-in support covers one standard Uniswap V2-style pool with a 0.3% fee. V3, V4, hooks, and unusual tokens need a verified adapter.

<details>
<summary>Try a local example</summary>

**Runtime:** Python 3.12+.

Run from the repository root with a new output path. This example uses simulated data and makes no live network requests.

```sh
python3 skills/exit-doctor/scripts/analyze_exit.py skills/exit-doctor/assets/synthetic-evidence.json --costs skills/exit-doctor/assets/synthetic-costs.json --scenarios skills/exit-doctor/assets/synthetic-scenarios.json --max-impact-bps 500 --out ../fc-exit-doctor-report-new.json
```

Open the output to explore the report before adding your own data.

</details>

<details>
<summary>Technical details and source</summary>

- Native support is one canonical 30-bps Uniswap V2-style pool with standard-token assumptions.
- V3, V4 hooks, bonding curves, split routing, native wrapping, transfer taxes, and rebasing need verified external adapters.
- A router-call return is not a measured recipient balance change.
- Unknown additional costs leave net proceeds unknown; the largest passing tested size is not a global maximum or allocation recommendation.
