The docs use Fumadocs and Next.js. Pages are written in MDX and exported as a static site.

## Find the right file

| Path | What it contains |
| --- | --- |
| `skills/` | Skill instructions, helpers, examples, and tests |
| `operator/` | Monitoring service, storage, and recovery tools |
| `docs-site/content/docs/` | Documentation pages and sidebar order |
| `docs-site/app/` | Site routes and theme |
| `references/` | Integration notes |
| `manifest.json` | Exported skill file inventory and hashes |

## Edit a page

Update its `.mdx` file. Keep the title and description short. Add new pages to the folder’s `meta.json`.

Use `/docs/…/` for site links and full GitHub URLs for source files. Examples should run from the repository root, use a fresh output path, and clearly identify simulated data.

Keep the explanation brief. Put detailed setup or limitations in a reference page or an expandable section.

## Check docs changes

Use Node.js 24 or newer:

```sh
npm ci
npm run build
npm run check:docs
```

The build checks types and creates the static site in `out/`. The docs check verifies pages, links, assets, and search results for all 16 skills.

## Check code changes

Use Python 3.12 or newer for the package runner:

```sh
python3 scripts/check_package.py
python3 scripts/check_package.py --tests
npm run test:operator
```

The first command verifies the exported file inventory. The next two run the skill and Operator suites. Update the manifest when exported skill files change; docs-only edits do not require new skill hashes.

GitHub CI runs the package, Operator, and docs checks. These checks use local evidence and do not contact live trading providers.

## Host the docs

Serve the generated `out/` directory with directory-index support. The exported `/search-index.json` must remain accessible for search.

The site has no built-in authentication. Configure access and search indexing for your intended audience before publishing. Use the existing hosting project when updating its deployment.

Keep provider credentials, environment files, runtime journals, and generated output out of Git.
