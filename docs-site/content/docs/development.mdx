## Repository layout

| Path | Purpose |
| --- | --- |
| `skills/` | Complete exported skill folders, helpers, fixtures, and references |
| `manifest.json` | Versioned inventory of skill paths, hashes, and byte lengths |
| `scripts/check_package.py` | Package integrity and isolated skill test runner |
| `scripts/research_demo.py` | Offline three-skill research handoff |
| `references/` | Cross-package integration notes |
| `docs-site/content/docs/` | Fumadocs MDX pages and sidebar metadata |
| `docs-site/app/` | Next.js routes, layout, and theme |
| `scripts/check_docs.mjs` | Static output, local link, and search-index checks |
| `out/` | Generated static site; excluded from Git |

## Edit a page

Create or update an `.mdx` file inside `docs-site/content/docs/`. Include a title and a description in frontmatter. Add a new page to the relevant `meta.json` ordering. Use root-relative site links such as `/docs/skills/circuit/` and full GitHub links for repository source.

Keep commands copyable from the repository root. Clearly identify synthetic examples and choose a new output path for commands that reject existing files. Check the actual helper's arguments before documenting a new command.

Fumadocs provides sidebar navigation, page outlines, searchable content, syntax highlighting, copyable code blocks, and a light/dark theme. The search index is generated at build time and consumed locally in the browser.

## Validate changes

From the repository root:

```sh
npm ci
npm run build
npm run typecheck
npm run check:docs
python3 scripts/check_package.py
```

`npm run build` compiles MDX and exports the Next.js site. The postbuild stage copies the public export to `out/`. `check:docs` checks the built routes and local asset/link targets, verifies that every manifest skill has a documentation page, and validates the static search payload.

For skill behavior changes, run the affected suite and the package runner as needed:

```sh
python3 scripts/check_package.py --tests
```

Docs-only edits do not require changes to exported skill hashes. Intentional edits under `skills/` require review and an updated manifest. Keep the package inventory valid and preserve scoped license notices.

## Publishing

The static output can be hosted by a service that supports directory indexes and the exported route files. Serve `/search-index.json` as the exported JSON payload. Preserve private access for this repository's documentation; the site itself does not implement an authentication system.

The checked-in hosting manifest identifies the existing private documentation site. Reuse that identity when updating it. Local environment files, provider credentials, generated output, caches, and runtime journals stay out of Git.
