# Disclosure, valuation and performance integration

CATALYST, Night Desk and Agent Arena are independent executable skills. Their
versioned JSON reports can be ingested by application adapters. This package
does not deploy a service or modify the FYNCH/Ape repositories.

## Ownership and identity

Keep WATCHTOWER transaction capture independent of SEC HTTP requests and XML
processing. Run CATALYST using its own SQLite database and bounded collection
cycles. Feed retained exact-pool observations from the application's existing
canonical ingestion path to CATALYST's response analyzer. A decoded transaction
alone is not a supported pool price or a wallet execution quote.

Resolve company CIK and the precise security class to the chain 4663 token
address before associating filings. Symbols and display names are not join
keys. Keep mapping evidence and when that mapping became known. A retrospective
mapping can help research; it must not become an allegedly live historical pick.

Night Desk values a specific asset and, when supplied, a specific wallet, raw
amount and route. Preserve unsupported, stale, halted and missing-cost states.
A retained quote or successful wallet-call simulation does not authorize Ape
execution. Keep the original evidence and route gates with the application.

Agent Arena consumes complete frozen portfolio evidence for its declared scope.
Its performance report is a separate accounting product. Associating a filing
with a profitable wallet period does not establish that the filing or agent
caused the return. Do not infer absent transfers, unpriced inventory or failed
attempt costs from a candidate feed.

## Offline event-to-valuation interchange

`scripts/compose_research.py` consumes a `CatalystEvents@1` export (`schemaVersion`) and one or
more `NightDeskReport@1` reports. For example, with reports already generated by
their respective skills:

```sh
python3 scripts/compose_research.py \
  --events /absolute/path/events.json \
  --valuation /absolute/path/valuation.json \
  --as-of 2026-09-08T16:00:00Z \
  --out /absolute/path/new-research-bundle.json
```

Use an actual view timestamp. The CLI creates a new output file. Inputs are
bounded to 16 MiB per file and 10,000 events/reports per composition.

The output `MSKResearchBundle@1` retains event evidence, complete unmodified
valuation reports, content hashes, source coverage, missing associations and
excluded future inputs. Exact asset addresses determine matches. Report hashes
deduplicate identical reports while retaining different wallets, sizes and
routes. Mappings known only after the view timestamp cannot create links.
Retrospective mappings and valuations preceding the disclosure observation
remain explicitly labelled. Details downloaded or parsed after the view are
excluded; missing detail-readiness timestamps cannot establish historical
knowledge. Original event payloads retain raw mapping evidence, including later
mappings. Historical displays must use `links`/`unavailable` and timing labels,
not render raw `event.associations` as facts known at the view time. Schema
checking here validates the handoff, not
the financial correctness or authenticity of an arbitrary supplied report.

## Application acceptance checks

- Display the reported transaction date separately from filing acceptance and
  first observation. Amended disclosures remain distinguishable.
- Keep equity-share prices, adjusted token prices and executable output units
  distinct. Preserve source timestamps and FX evidence.
- Recompute or retract response evidence when an upstream block is orphaned.
  Do not advance a canonical response cursor past missing coverage.
- Persist the event and selected evidence before recording subsequent outcomes.
  Missing outcomes remain in the candidate universe.
- Expose collector backlog, retries, age and failed requests. A running process
  is not evidence of current or complete data.
- Validate wallet performance with opening and closing equity, external flows,
  open inventory, liabilities and failed-attempt costs. Content hashes detect
  modification relative to a trusted checkpoint; they do not prove authorship
  or a complete wallet history.

Live deployment needs configured source access, a host, retention ownership and
an application consumer. Those are deployment inputs; offline fixture outputs
must remain labelled synthetic.
